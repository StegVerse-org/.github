# Organization Resident Runtime

This directory is the canonical home for StegVerse-org resident-runtime activation metadata and entrypoints.

Application repositories expose capabilities to this runtime. All organization-crossing ingress/egress is generated by StegVerse-org/.github using Interlock/InTr.

## Ledger stores

`ledger_store.py` maps the ledger's keys (`HEAD.json`, `receipts/<hex>.json`,
`source-receipts/<hex>.json`) onto a substrate. Which store is used follows
only from the location supplied as `STEGVERSE_ORG_LEDGER_ROOT` or
`STEGVERSE_REPO_LEDGER_ROOT`:

- a filesystem path opens `PosixLedgerStore`, as it always has;
- `git+<repository>#<ref>` opens `GitLedgerStore`: documents are blobs in the
  tree the ref names, each append is one commit, and it is published with
  `git update-ref <ref> <new> <old>`, git's atomic compare-and-swap. A writer
  that loses the comparison publishes nothing. Both halves are required and
  the ref must be fully qualified (`refs/...`). Only the stdlib and the `git`
  command are used.

With nothing supplied, every append still fails closed with
`LEDGER_LOCATION_REQUIRED_FROM_MATERIALIZER`.

No path, repository, ref, branch or workflow here is the organization's
ledger, and none is designated by being openable. Designating the
organization's sovereign ledger root is an owner decision, pending on
StegVerse-org/LLM-adapter#368 (`ORG_LEDGER_ROOT_NOT_DESIGNATED`).
